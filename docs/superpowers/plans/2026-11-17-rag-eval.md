# EU AML RAG Evaluation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a RAG over EU and Portuguese AML regulation in three configurations, evaluate them on a reviewed test set (Ragas plus own metrics), and publish a comparative report.

**Architecture:** One Python package, `eurag`, with a CLI (`eurag ingest | testset | run | evaluate | calibrate | report`). Each RAG configuration is a YAML file. Every stage writes its output to disk (chunks, index, answers, scores), so later stages rerun without paying again. Paid stages print a cost estimate and ask for confirmation.

**Tech Stack:** Python 3.13, uv, `ragas==0.4.*`, `langchain==1.5.*`, `langchain-qdrant==1.1.*`, `langchain-anthropic`, `langchain-huggingface` + `sentence-transformers` (BGE-M3), `fastembed` (`Qdrant/bm25` sparse), `qdrant-client` (local mode), `docling`, `beautifulsoup4`, `matplotlib`, `pytest`, `ruff`.

**Spec:** `docs/superpowers/specs/2026-11-17-rag-eval-design.md`

## Global Constraints

- No code, text or diagram copied from `junidepieri-design/eval-001-rag-evaluation-template` or `genai-001-regulatory-rag-bsa-aml` (unlicensed).
- Source documents are never committed. `corpus/manifest.yaml` (URL, title, language) and `data/raw/lock.json` (sha256, retrieved_at) are.
- Answer model `claude-opus-5-5`; Ragas judge `claude-haiku-5-5`. Budget ceiling 25 USD total. Every paid command prints an estimate and requires `--yes` or an interactive "y".
- Opus 5.5 / Haiku 5.5 reject `temperature`/`top_p`: never send sampling parameters.
- Retrieval metrics use no LLM.
- Only test-set rows with `origin` in {`reviewed`, `handwritten`} are evaluated.
- Default `top_k = 5`. Fixed chunking: 1000 characters, 150 overlap.
- Code, identifiers, commits in English; `README.md` + `README.pt.md`.
- Unit tests run offline with no API key and no model downloads; tests needing downloads are marked `models` and skipped in CI.

## Review Focus

1. A question whose expected article is split across several chunks must still count as a retrieval hit when any part is retrieved. Pinned in Task 7 (`test_hit_when_any_part_of_article_retrieved`).
2. Citations written in slightly different forms ("[AMLR, art. 20]", "[AMLR, Article 20]", "[Aviso 1/2022, art. 5.º]") must match the same expected citation. Pinned in Task 5 (`test_parse_citation_variants`).
3. A crashed or interrupted `run` must resume without paying again for answers already saved. Pinned in Task 5 (`test_cache_skips_saved_answers`).
4. A config edited after a run (e.g. `top_k` changed) must not reuse stale cached answers. Pinned in Task 5 (`test_cache_key_changes_with_config`).
5. A Ragas judge call that fails for one question must leave that metric empty for that question and keep the rest, not abort the whole evaluation. Pinned in Task 8 (`test_failed_metric_is_recorded_not_raised`).
